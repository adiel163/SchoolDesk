## 2. Environment Setup

1. **Copy `.env.example`** to `.env` and fill in the values:

```env
# Database
DATABASE_URL="postgresql://neondb_owner:password@ep-name.region.aws.neon.tech/neondb?sslmode=require"

# Better‑Auth
AUTH_SECRET="a-very-secret-key-at-least-32-characters-long"
NEXT_PUBLIC_APP_URL="http://localhost:3000"
```

2. **Run migrations** (once the DB is created):

```bash
npx drizzle-kit push   # pushes schema to Neon
# or, to generate & run SQL manually:
npx drizzle-kit generate   # creates db/0000_*.sql
```

3. **Start the dev server**:

```bash
npm run dev
```

The application will be available at `http://localhost:3000`.  
The first sign‑up creates a user; an admin can be created manually via a one‑off SQL insert or through the UI’s “Create Admin” flow (see *Admin User Guide* below).

## 3. Authentication & Role Guard

- **Better‑Auth** is configured in `auth.ts` with email/password.
- A `role` field is added to the user session (`admin`, `parent`, `teacher`, `bursar`).
- **Middleware** (`middleware.ts`) rewrites any request to `/admin/*` when the user is not an admin, redirecting to `/login`.
- Every **server action** also checks `user.role === 'admin'` before executing business logic (the actions currently rely on the caller being authenticated as admin; you can add the guard at the API route level if needed).

```ts
// middleware.ts (excerpt)
if (path.startsWith("/admin")) {
  const authResult = await betterAuth({ request }).then((res) => res.user?.role);
  if (authResult !== "admin") {
    return NextResponse.redirect(new URL("/login", request.url));
  }
}
```

## 4. Schema Overview

Key tables (UUID primary keys, `createdAt`/`updatedAt`, archive/flags):

| Table | Important Columns |
|-------|-------------------|
| `academic_sessions` | `id`, `name`, `isActive`, `startDate`, `endDate` |
| `terms` | `id`, `name`, `sessionId` (FK), `isActive`, `startDate`, `endDate` |
| `classes` | `id`, `name`, `sessionId` (FK), `gradeLevel` |
| `subjects` | `id`, `name`, `code` |
| `teachers` | `id`, `fullName`, `email`, `phone`, `status` (true=active) |
| `students` | `id`, `admissionNumber`, `firstName`, `lastName`, `gender`, `classId`, `termId`, `parentId`, `status` |
| `results` | `id`, `studentId`, `subjectId`, `termId`, `score`, `grade`, `published` (default `false`) |
| `class_subjects` | junction: `classId`, `subjectId` |
| `teacher_classes` | junction: `teacherId`, `classId` |
| `teacher_subjects` | junction: `teacherId`, `subjectId` |
| `audit_logs` | `id`, `action`, `entityType`, `entityId`, `performedBy`, `performedAt`, `details` |

Relationships are expressed via Drizzle foreign keys; many‑to‑many junctions allow assigning teachers to classes/subjects and subjects to classes.

## 5. Server Actions (Zod‑validated)

All actions live in `server/actions/` and follow the same pattern:

1. **Zod schema** validates the payload.
2. **Business logic** queries the Drizzle `db` instance.
3. **Return shape**: `{ success: boolean; data?: T; error?: string }`.

### 5.1 Classes

| Action | Description |
|--------|-------------|
| `createClass({name, sessionId, gradeLevel})` | Creates a new class within a session. |
| `updateClass({id, name, gradeLevel})` | Updates an existing class. |
| `deleteClass({id})` | Deletes a class if no students are assigned. |
| `listClasses(sessionId)` | Returns all classes for a session. |

### 5.2 Students

| Action | Description |
|--------|-------------|
| `createStudent({admissionNumber, firstName, lastName, gender, dateOfBirth, classId, termId, parentId})` | Adds a student linked to a class/term and optionally a parent auth user. |
| `importStudentsCSV(csvText)` | Bulk‑imports students from a CSV string. Returns `{created, errors}`. Each row is validated; errors are collected and reported. |

### 5.3 Teachers

| Action | Description |
|--------|-------------|
| `createTeacher({fullName, email, phone, status})` | Creates a teacher record; email must be unique. |
| `updateTeacher({id, fullName, email, phone, status})` | Updates teacher data. |
| `deactivateTeacher({id})` | Sets `status` to `false` (deactivated). Audited. |

### 5.4 Subjects

| Action | Description |
|--------|-------------|
| `createSubject({name, code})` | Creates a subject. |
| `updateSubject({id, name, code})` | Updates a subject. |
| `assignSubjectToClass({subjectId, classId})` | Links a subject to a class via the `class_subjects` junction. |

### 5.5 Results (Publish/Unpublish)

| Action | Description |
|--------|-------------|
| `publishResult({resultId, published})` | Toggles the `published` flag on a result. When `true`, the result is visible to parents; when `false`, it is hidden. |
| `createResult({studentId, subjectId, termId, score, grade})` | Inserts a new result (always `published: false`). |
| `getPublishedResults(studentId, termId)` | **Helper** for other modules. Returns all published results for the given student & term, joined with subject names. |

### 5.6 Audit Logging

- The `publishResult` and `deactivateTeacher` actions **comment** a TODO to insert a row into `audit_logs`. Implement the insert as:

```ts
await db.insert(auditLogs).values({
  action: published ? "RESULT_PUBLISHED" : "RESULT_UNPUBLISHED",
  entityType: "RESULT",
  entityId: resultId,
  performedBy: <admin-user-id>, // obtain from Better‑Auth session
  details: `Admin toggled result visibility`,
  performedAt: new Date(),
});
```

## 6. UI (shadcn‑ui + Tailwind)

The admin UI is **not** fully built in this initial code drop, but the following components are recommended (you can generate them with `npx shadcn@latest add`):

- `table` – responsive data tables with search/filter.
- `pagination` – server‑side or client‑side page navigation.
- `dialog` – confirmation dialog for publish/unpublish and deactivate actions.
- `input` – forms for CRUD operations (already Zod‑validated on the server).
- `file-upload` – CSV import component that calls `importStudentsCSV`.
- `empty-state` & `loading-state` – placeholder UI while data fetches.

**Search / Pagination** can be implemented by passing `searchTerm` and `page`/`pageSize` to the server actions; the actions currently return all rows, but you can add `where` clauses on `name ilike `%${searchTerm}%` if needed.

**Empty states** should display a friendly message such as “No classes found. Add a class using the form above.”

**Loading states** use the `loading` placeholder from React Server Components or the `skeleton` shadcn component.

## 7. Helper for Other Modules: `getPublishedResults`

Other feature modules (e.g., Results, Reports) can import the helper:

```ts
import { getPublishedResults } from "@/server/actions/results";

// Usage in a React component or server component:
const published = await getPublishedResults(studentId, termId);
// published is an array of {
//   resultId: string,
//   subjectName: string,
//   score: number,
//   grade: string | null,
//   published: boolean,
// }
```

The helper **only returns rows where `published = true`**, ensuring unpublished results are never exposed to parents.

## 10. Admin User Guide (quick reference)

| Task | UI / API | Permissions |
|------|----------|-------------|
| **Create academic session** | `POST /admin/sessions` (server action) | Admin |
| **Create term** | `POST /admin/terms` (server action) | Admin |
| **Add class** | `POST /admin/classes` (server action) | Admin |
| **List classes** | `GET /admin/classes?sessionId=…` | Admin |
| **Publish result** | `POST /admin/results/:id/publish` (server action) | Admin |
| **Unpublish result** | `POST /admin/results/:id/unpublish` (server action) | Admin |
| **CSV import students** | Upload file → `importStudentsCSV` action | Admin |
| **Deactivate teacher** | `POST /admin/teachers/:id/deactivate` (server action) | Admin |
| **View audit log** | (future) `GET /admin/audit-logs` | Admin |

All admin routes are under `/admin/*` and are protected by the middleware; unauthenticated or non‑admin users are redirected to the login page.
