# SchoolDesk — Private Nigerian Secondary School Portal

**Stack:** Next.js 16 (App Router), TypeScript, Neon Postgres, Drizzle ORM, Better Auth, Zod, Tailwind CSS / shadcn‑ui  
**Roles:** Parent, Teacher, Bursar, Admin  
**Admin routes:** `/admin/*` — Admin‑only, enforced in middleware and every server action.

---

## 1. Getting Started

```bash
# install dependencies (run once)
npm install

# environment variables
cp .env.example .env
# edit .env with your Neon Postgres URL and Better‑Auth secrets

# run database migrations
npx drizzle-kit push   # pushes schema to Neon

# start the dev server
npm run dev
# open http://localhost:3000
```

### `.env.example`

```env
# Database (Neon)
DATABASE_URL="postgresql://neondb_owner:password@ep-name.region.aws.neon.tech/neondb?sslmode=require"

# Better‑Auth
AUTH_SECRET="a-very-secret-key-at-least-32-characters-long"
NEXT_PUBLIC_APP_URL="http://localhost:3000"
```

## 3. Authentication & Role Guard

- **Better‑Auth** (`auth.ts`) provides email/password sign‑in.
- A `role` field is added to the session (`admin`, `parent`, `teacher`, `bursar`).
- **Middleware** (`middleware.ts`) rewrites any `/admin/*` request when the user is not an admin, redirecting to `/login`.
- Server actions should also verify `user.role === 'admin'` before proceeding (the actions currently assume the caller is authenticated as admin; you can add the check at the route level if needed).

```ts
// middleware.ts (excerpt)
if (path.startsWith("/admin")) {
  const { user } = await betterAuth({ request });
  if (!user || user.role !== "admin") {
    return NextResponse.redirect(new URL("/login", request.url));
  }
}
```

## 4. Database Schema (highlight)

| Table | Key Columns |
|-------|-------------|
| `academic_sessions` | `id`, `name`, `isActive`, `startDate`, `endDate` |
| `terms` | `id`, `name`, `sessionId` (FK), `isActive`, `startDate`, `endDate` |
| `classes` | `id`, `name`, `sessionId` (FK), `gradeLevel` |
| `subjects` | `id`, `name`, `code` |
| `teachers` | `id`, `fullName`, `email`, `phone`, `status` (true=active) |
| `students` | `id`, `admissionNumber`, `firstName`, `lastName`, `classId`, `termId`, `parentId`, `status` |
| `results` | `id`, `studentId`, `subjectId`, `termId`, `score`, `grade`, `published` (default `false`) |
| `audit_logs` | `id`, `action`, `entityType`, `entityId`, `performedBy`, `performedAt`, `details` |

Relationships are defined via Drizzle foreign‑key constraints; many‑to‑many junctions (`class_subjects`, `teacher_classes`, `teacher_subjects`) enable flexible assignments.

## 5. Server Actions (Zod‑validated)

All actions live in `server/actions/` and return `{ success, data?, error? }`.

### 5.1 Classes

- `createClass({name, sessionId, gradeLevel})`
- `updateClass({id, name, gradeLevel})`
- `deleteClass({id})`
- `listClasses(sessionId)`

### 5.2 Students

- `createStudent({admissionNumber, firstName, lastName, gender, dateOfBirth, classId, termId, parentId})`
- `importStudentsCSV(csvText)` → `{created, errors}`

### 5.3 Teachers

- `createTeacher({fullName, email, phone, status})`
- `updateTeacher({id, fullName, email, phone, status})`
- `deactivateTeacher({id})`

### 5.4 Subjects

- `createSubject({name, code})`
- `updateSubject({id, name, code})`
- `assignSubjectToClass({subjectId, classId})`

### 5.5 Results (Publish/Unpublish)

- `publishResult({resultId, published})` – toggles visibility to parents.
- `createResult({studentId, subjectId, termId, score, grade})` – new results are unpublished by default.
- `getPublishedResults(studentId, termId)` – **helper** for other modules; returns only published rows joined with subject names.

### 5.6 Audit Logging

- `publishResult` and `deactivateTeacher` include a TODO comment to insert a row into `audit_logs`. Implement as:

```ts
await db.insert(auditLogs).values({
  action: published ? "RESULT_PUBLISHED" : "RESULT_UNPUBLISHED",
  entityType: "RESULT",
  entityId: resultId,
  performedBy: <admin-user-id>,
  details: "Admin toggled result visibility",
  performedAt: new Date(),
});
```

## 6. Helper for Other Modules: `getPublishedResults`

Other feature modules can import this utility to know which results are visible to parents.

```ts
import { getPublishedResults } from "@/server/actions/results";

const published = await getPublishedResults(studentId, termId);
// published = [
//   { resultId, subjectName, score, grade, published },
// ]
```

The helper **only returns rows where `published = true`**, ensuring unpublished results never appear to parents.

## 7. Admin User Guide (quick reference)

| Task | API / UI | Permissions |
|------|----------|-------------|
| Create academic session | `POST /admin/sessions` (server action) | Admin |
| Create term | `POST /admin/terms` (server action) | Admin |
| Add class | `POST /admin/classes` (server action) | Admin |
| List classes | `GET /admin/classes?sessionId=…` | Admin |
| Publish result | `POST /admin/results/:id/publish` (server action) | Admin |
| Unpublish result | `POST /admin/results/:id/unpublish` (server action) | Admin |
| CSV import students | Upload file → `importStudentsCSV` action | Admin |
| Deactivate teacher | `POST /admin/teachers/:id/deactivate` (server action) | Admin |
| View audit log | (future) `GET /admin/audit-logs` | Admin |

All admin routes are under `/admin/*` and are protected by the middleware; unauthenticated or non‑admin users are redirected to the login page.
